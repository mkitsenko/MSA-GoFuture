Предлагается следующая логика зависимостей, подключений и маршрутизаций в случае отказа:

По регионам:
- Маршрутизация происходит через определение Региона пользователя через GeoIP
- Запрос направляется в ближайший Регион N
- Если приложения Региона R1 не отвечают, запросы направляются в Region R2
- Между БД регионов R1 и R2 настроена асинхронная репликация данных 

По зонам доступности:
- Базы данных Зоны А являются ведущими, зоны Б - ведомыми. Между ними настроена синхронная репликация Ведущая -> Ведомая.
- Все приложения направляют запросы в Ведущую БД (А).
- В случае отказа Базы данных А, база Б становится Ведущая, база - Ведомая. После восстановления Базы А (Ведомая) в нее происходит репликация из Базы Б (Ведущая).
- Маршрутизатор направляет запрос в Приложение (сервис) Зоны А, если Приложение Зоны A недоступно - происходит маршрутизация в приложение (сервис) Зоны Б.

Точки отказа и действия:

| # | Точка отказа                      | Действие                                                                                      |
|:-:|:----------------------------------|:----------------------------------------------------------------------------------------------|
| 0 | Запрос в маршрутизатор Региона R1 | Маршрутизация в Регион R2                                                                     |
| 1 | Запрос в Приложение\Сервис        | Маршрутизация в Приложение\Сервис соседней Зоны доступности                                   |
| 2 | Отказ БД                          | Смена ролей БД Ведущий<->Ведомый. Направление запроса в Ведущую БД.                           |
| 3 | Отказ Внешних сервисов            | Сохранение операций в OutOfBox. Ожидание восстановления Внешних сервисов, выполнение операции |
